Mock Test — Exam Format & Blueprint

The SnowPro Core COF-C03 exam is a proctored, multiple-choice test. Use the official exam guide at learn.snowflake.com for booking and policy updates; the figures below reflect the current blueprint as verified Jul 2026.

Revision tactic: Allocate study hours roughly proportional to domain weight, but spend extra time on domains where hands-on labs were thin. Domain 1 (31%) plus Domain 2 (21%) together are over half the exam — architecture, warehouses, Cortex, and performance tuning matter most.

Practice-question strategy

  1. First pass (45 min): Answer every question; flag uncertain ones. Do not linger — the clock is tight at ~69 seconds per question.
  2. Eliminate traps: Cross out answers that confuse warehouse vs serverless billing, metadata vs data scans, or Gen2 size limits (5XL/6XL = Gen1 only).
  3. Scenario questions: Identify the constraint first (latency, cost, security, edition). Match to the decision tree below before reading all four options.
  4. Second pass: Revisit flagged items with remaining time. Change an answer only when you recall a specific rule (e.g. resource monitors do not cap AI spend).
  5. Post-mock: For each wrong answer, note the course section — use the domain table above to schedule targeted revision.

Decision Trees

Which loading pattern?

How fresh must data be?
Batch (hours+) → COPY INTO + scheduled task
Micro-batch (minutes) → Snowpipe
Near real-time → Snowpipe Streaming / dynamic tables
Query lake files in place → External table or Iceberg

Which warehouse?

  • Standard WH — SQL, BI, general ETL.
  • Multi-cluster (Enterprise+) — concurrent user spikes (scale out).
  • Snowpark-optimized — in-warehouse Python/ML training.
  • Gen2 (XS–4XL) — newer hardware generation when size fits; 5XL/6XL require Gen1.
  • Separate WH per workload — always separate ETL from BI for exam answers.

CDC approach?

NeedPattern
Track row changes after commitStream on table → task MERGE
Declarative pipeline with lag SLADynamic table
External orchestrationExternal task + stream (less common on exam)

Recovery scenario?

  • Accidental drop → UNDROP within retention window (s03).
  • Point-in-time → Time Travel AT/OFFSET query or clone.
  • Cross-region DR → replication + failover (Business Critical+, s12).

AI feature choice?

  • Unstructured PDF Q&A fields → AI_EXTRACT
  • Full document text/structure → AI_PARSE_DOCUMENT
  • Product doc search / RAG → Cortex Search
  • Metric questions on curated model → Cortex Analyst
  • Tabular churn/scoring → SNOWFLAKE.ML.CLASSIFICATION

Common Exam Traps

  • Metadata queries do not need a running warehouse.
  • Fail-safe is not user-configurable; Time Travel is.
  • Transient tables have no Fail-safe; temporary have session scope.
  • Secure views required for shares — non-secure views expose definitions.
  • Resource monitors cap assigned warehouse compute + related cloud-services credits — not serverless, storage, or AI.
  • Gen2 sizing — XS–4XL on Gen2; 5XL/6XL require Gen1.
  • AI_PARSE_DOCUMENT — 100 MB, up to 2,000 pages (Apr 2026).
  • Cortex Search vs Cortex Analyst — similarity retrieval vs governed NL→SQL on semantic models.
  • External tables are read-only; Iceberg tables support ACID writes via external volumes.

Query Cookbook (High-Yield Patterns)

SELECT CURRENT_ROLE(), CURRENT_WAREHOUSE(), CURRENT_DATABASE(), CURRENT_SCHEMA();

COPY INTO my_table FROM @my_stage
  FILE_FORMAT = (TYPE = CSV SKIP_HEADER = 1)
  ON_ERROR = CONTINUE
  MATCH_BY_COLUMN_NAME = CASE_INSENSITIVE;

CREATE STREAM orders_stream ON TABLE raw_orders;
CREATE TASK merge_orders WAREHOUSE = etl_wh SCHEDULE = '5 MINUTE'
  WHEN SYSTEM$STREAM_HAS_DATA('orders_stream')
AS
  MERGE INTO curated_orders t
  USING (SELECT * FROM orders_stream) s
  ON t.id = s.id
  WHEN MATCHED THEN UPDATE SET t.val = s.val
  WHEN NOT MATCHED THEN INSERT (id, val) VALUES (s.id, s.val);

SELECT * FROM employees AT(OFFSET => -3600);

SELECT warehouse_name, SUM(credits_used) AS credits
FROM snowflake.account_usage.warehouse_metering_history
WHERE start_time >= DATEADD('day', -7, CURRENT_TIMESTAMP())
GROUP BY 1 ORDER BY 2 DESC;

Interview questions

Try to answer each one before opening it.

Which two statements about Snowflake's architecture are correct? (A) Virtual warehouses store micro-partitions locally as the system of record. (B) Cloud Services handles authentication and query parsing without needing a warehouse for metadata queries. (C) Database Storage holds data in cloud object storage as micro-partitions. (D) Suspending a warehouse deletes Time Travel history.Exam

Answer: B and C. Snowflake separates compute (virtual warehouses) from storage (micro-partitions in S3/Azure/GCS). Cloud Services coordinates auth, parsing, and metadata operations — SHOW, DESCRIBE, and DDL do not require an active warehouse. (A) is wrong because warehouses cache data temporarily but do not own storage. (D) is wrong — suspending compute does not delete table data or Time Travel; it only stops billing for that warehouse.

A product team wants semantic search over PDF release notes with optional RAG summarisation. Which feature fits best? (A) Cortex Analyst (B) Cortex Search (C) SNOWFLAKE.ML.CLASSIFICATION (D) Secure data shareExam

Answer: B. Cortex Search maintains embeddings on text columns, supports SEARCH_PREVIEW, and pairs with AI_COMPLETE for RAG. Cortex Analyst (A) generates SQL against semantic models for structured KPIs — wrong fit for unstructured PDFs. ML CLASSIFICATION (C) trains on tabular features, not document search. A data share (D) delivers tables to another account; it does not provide similarity search inside the warehouse.

Your workload requires a Standard warehouse at size 5XL with Gen2 hardware. What is true? (A) Create the warehouse with GENERATION = '2' at size 5XL. (B) Use Gen1 — Gen2 supports XS–4XL only; 5XL and 6XL require Gen1. (C) Use Snowpark-optimized instead — it replaces Gen2. (D) Multi-cluster warehouses automatically upgrade to Gen2 at 5XL.Exam

Answer: B. Standard Gen2 supports XS through 4XL only. Sizes 5XL and 6XL require Gen1 — a common COF-C03 trap. (A) would fail or is not supported depending on account settings. (C) confuses warehouse type (Snowpark-optimized vs Standard) with hardware generation — they are orthogonal. (D) is fabricated; multi-cluster controls concurrency, not generation or maximum size tier.

When are cloud-services credits typically waived? (A) When daily cloud-services usage is at or below 10% of warehouse compute credits consumed that day. (B) When the warehouse is X-Small. (C) When queries use the result cache. (D) When the account has Business Critical edition.Exam

Answer: A. Cloud-services charges (orchestration, metadata) are waived when daily usage stays within 10% of compute credits used that day — a high-yield exam fact. (B) warehouse size does not determine the waiver. (C) result cache avoids re-execution but is unrelated to the cloud-services percentage rule. (D) edition affects features like Tri-Secret Secure, not the 10% waiver formula.

Query Profile shows significant bytes spilled to remote storage on a large join. What is the best first remediation? (A) Enable Search Optimization Service on all tables. (B) Scale up the warehouse or simplify/batch the query. (C) Convert tables to external tables. (D) Disable the result cache.Exam

Answer: B. Spilling means the warehouse ran out of local memory for operators — scaling up adds RAM per node, and rewriting/batching reduces peak memory. (A) SOS helps selective point lookups, not arbitrary large joins. (C) external tables still need compute and do not fix spill on their own. (D) disabling cache does not address memory pressure and may increase cost without helping spill.

Which two credit types count toward a resource monitor assigned to a warehouse? (A) Credits used by that virtual warehouse's compute. (B) Serverless task credits anywhere in the account. (C) Cloud-services credits associated with queries on that warehouse. (D) AI_SERVICES Cortex token spend.Exam

Answer: A and C. Resource monitors cap assigned user-managed warehouses — their compute credits plus related cloud-services credits on those warehouses. (B) serverless tasks bill separately and are not capped by warehouse resource monitors. (D) Cortex/AI_SERVICES spend is also outside monitor scope — use budgets, alerts, and usage reviews instead. Storage is never capped by resource monitors either.

A pipeline must stay within five minutes of source changes with minimal operational overhead. The transformation is a single SELECT with aggregations. Best approach? (A) Stream + task MERGE written manually (B) Dynamic table with appropriate TARGET_LAG (C) External table only (D) Repeated COPY INTO from a stage every secondExam

Answer: B. Dynamic tables declare a SELECT and TARGET_LAG; Snowflake manages incremental refresh — ideal for declarative aggregations with a freshness SLA. (A) works but adds MERGE authoring and task operations. (C) external tables do not maintain transformed aggregates inside Snowflake. (D) one-second COPY is not a supported micro-batch pattern and would be costly and fragile.

Trust Center flags a recommendation to reduce ACCOUNTADMIN users. What is Trust Center primarily designed for? (A) Forecasting monthly credit bills (B) Scanning security hygiene and compliance gaps (C) Tuning warehouse auto-suspend settings (D) Indexing columns for Cortex SearchExam

Answer: B. Trust Center surfaces MFA gaps, stale users, over-privileged roles, and data-protection issues — a governance posture dashboard. (A) describes Cost Insights and metering views. (C) is manual warehouse administration. (D) is unrelated to Trust Center's security scan scope.

Which two statements about parameter scope are correct? (A) MIN_DATA_RETENTION_TIME_IN_DAYS is account-only. (B) USE_CACHED_RESULT is set with ALTER USER as the primary scope. (C) TIMEZONE can be overridden at session level. (D) MAX_CONCURRENCY_LEVEL is set with ALTER ACCOUNT only.Exam

Answer: A and C. MIN_DATA_RETENTION_TIME_IN_DAYS is account-only — session-level ALTER attempts fail. TIMEZONE cascades account → user → session, and session wins — so C is correct. (B) is wrong: USE_CACHED_RESULT is a session parameter. (D) is wrong: MAX_CONCURRENCY_LEVEL is set on the warehouse with ALTER WAREHOUSE, not the account.

You need read-only access to CSV files already in S3 without loading them into native storage. What is true of external tables? (A) They support INSERT and MERGE. (B) Column values map via expressions like VALUE:c1. (C) Fail-safe protects external table files in Snowflake storage. (D) Time Travel retains 90 days of file versions automatically.Exam

Answer: B. External tables are read-only metadata overlays on staged files; columns bind with VALUE:cN casts. (A) DML is not supported — use native or Iceberg tables for writes. (C) and (D) external data is not stored in Fail-safe or Time Travel; refresh metadata with ALTER EXTERNAL TABLE … REFRESH instead.

A provider wants to share live data with a consumer in another account without copying the dataset. Which requirement is mandatory for shared views? (A) Views must be secure views. (B) Consumer must use the same cloud region only. (C) Provider must grant SELECT on the consumer's warehouse. (D) Shared tables must be transient.Exam

Answer: A. Shares expose secure views (and secure UDFs) so consumers cannot view underlying definitions — non-secure views are not shareable for this reason. (B) cross-region sharing is possible with replication (extra cost). (C) backwards — consumers use their own warehouses. (D) shared objects are typically permanent tables or secure views, not transient scratch tables.

Hourly batch files arrive in a stage; latency requirement is hours, not seconds. Best loading pattern? (A) Snowpipe auto-ingest (B) COPY INTO on a scheduled task (C) Snowpipe Streaming (D) External function calling AWS LambdaExam

Answer: B. Batch hourly loads with hours of acceptable latency fit COPY INTO plus a scheduled task — simple and cost-predictable. (A) Snowpipe suits micro-batch/file-arrival automation when minutes matter. (C) Streaming targets low-latency row ingestion, overkill here. (D) external functions call out of Snowflake and do not replace stage loading for this pattern.
